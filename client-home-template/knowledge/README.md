# Клиентские знания

В эту директорию поступают только документы и записи конкретного клиента после отдельного onboarding.

До ingestion здесь нет бизнес-данных. Документы не копируются из другого клиентского контура, production-home, тестовых сессий или Git-репозитория.

## Контракт ingestion

1. Оператор указывает владельца, источник, тип данных, срок актуальности и разрешённую аудиторию.
2. Система сохраняет исходный документ в клиентском persistent home.
3. Индексатор создаёт chunks и retrieval index только внутри этого home.
4. Каждый ответ с использованием знания возвращает ссылку на документ и фрагмент.
5. Удаление документа удаляет его из retrieval index и создаёт audit event.
6. Пока для документа не сформированы chunks, индекс и проверка citation, он не считается доступным знанием.

Текущий release создаёт только изолированный root и контракт. Векторный backend включается отдельной версией release после реального ingestion/retrieval acceptance.
